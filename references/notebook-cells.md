# 围绕核心问题构建 Notebook

读取当前研究包，沿用核心假说、方法、对照和有效结果。Notebook 呈现当前实验的可运行教程，读者从问题出发，逐步看到输入如何变成结论。

## 读者的学习顺序

| 内容 | 读者需要理解什么 |
|---|---|
| 问题与判断依据 | idea 要改变什么，怎样通过比较判断 |
| 实际输入与参数 | 两组处理什么，改变什么，保持什么相同 |
| 方法与对照 | 先定义关键函数，再用当前输入调用，展示必要中间值 |
| 比较与结论 | 计算主指标，绘制有助判断的图表，解释实际发现 |

按概念组织单元，一组连续代码可以共用短说明。先与用户采用当天最小路线，每轮只完成其中一个教学步骤，可包含多个定义、调用和显示单元。保存后交付并结束当轮，等待反馈。已有路线直接沿用，不把每格当作审批。约 5 秒指聊天摘要与当前步概览的扫读目标，必要代码和科学解释保留在 Notebook。

“从零实现”指读者能从头理解和执行当前研究的关键实验。普通 Python 单元直接定义核心算法、干预、对照和指标，后续单元在当前内核调用这些定义。关键实现包括 idea 引入的干预及决定比较结果的控制逻辑，按当前研究包选定。成熟 SDK、数据读取和硬件接口可正常导入复用。

## 定义、执行与可选导出

核心代码使用普通 `def` 或确有需要的类定义。定义、实际调用、必要输出相邻呈现，紧密相关的短函数可以放在同一组单元。`%%writefile`、把源码字符串写入 `.py` 后再导入、`importlib.reload` 或 `%run` 不作为教学核心的定义与执行入口。展示源码文本或外部命令也不能替代关键方法的实际计算。

普通单元直接运行本页定义，不生成或覆写项目 Python 源码。实验结果、模型产物及代码生成研究中的候选代码可以按当前方案保存。含长任务的 Notebook 使用逐步运行方式；手动标签不会让 Jupyter 自动跳过这些单元。

用户需要独立脚本或部署包时，在完整定义后单独导出一次，导出独立于默认 Run All。导出使用已验证定义，说明目标文件并保留用户修改；普通阅读与运行无需先导出、再导入。远程硬件优先通过远程内核执行本页定义；已有作业接口按实际需要复用，并说明实际提交的实现。

## 每轮维护当前正文

采用步骤路线后先保存有效 Notebook 与第一步可见内容。每次交互只修改当前步骤，保存后交付文件或现有网址。保留直接帮助理解核心问题、方法、比较和结论的内容，以及执行所必需的简短设置。

- 将被取代的解释、重复代码与输出、无关诊断移出正文。用户编写或未保存的内容先保留，再按实际任务处理。
- 原始运行、失败回包、配置和排错细节保存在已有文件；需要恢复的决定简记到既有 `.research/session.md`。只链接帮助复现或解释当前比较的档案。
- 当前比较中的负结果、失败分支和反例属于科学内容，保留会影响判断的观察。旧排错过程只有仍解释当前结果时才进入正文。
- 接口连通、账本重放、权限说明和环境探测按实际阻断项处理。完成后给出必要状态，让正文继续进入核心实验。研究对象本身是这些机制时，按其科学作用展开。

当前步骤的代码与说明完成后即可交付。短测、待手动和已有运行分别标明，结果缺失不阻止保存代码。反馈到来后原位完善，保持依赖成立，保留原始证据。

## 短代码与短说明

编写 Notebook 代码和描述块时，使用宿主可用的 `ponytail` 与 `asd-ste100` 技能。ponytail 约束实现范围，ASD-STE100 的清晰表达原则用于说明。技能不可用时，沿用以下原则完成当前工作。

- 函数足够就用函数。使用直白名称和控制流，复用现有依赖。注释只解释代码未表达的必要原因。
- 先展示正常输入经过关键方法的过程。输入验证放在实际外部边界，内部沿用已建立的约定。保留真实权限、费用、资源释放和数据保护。
- 每组代码前通常用一到三句说明新增概念或关键动作。代码已清楚表达的输入和输出无需再复述。
- 比较完成后集中解释一次。写出实际差值和它回答的问题，只说明会改变当前判断的证据限制。参数、运行说明和相同限制各放在适用的位置。
- 中文一句讲一个意思，同一概念使用同一名称。术语首次说明后直接使用。英文操作句通常不超过 20 词，说明句通常不超过 25 词。必要推导按步骤展开；中文不机械套用英文词数，也不声称经过 STE 认证。

聊天摘要通常三四行：当前步骤、已保存内容、短测或待手动状态、文件／现有网址。需要反馈时只问一项会改变当前步骤的问题。说明和代码放在 Notebook，摘要保持可扫读。

## 中文结果与图表

数值说明对象、单位和指标方向。比较给出必要起点、终点与差值；区分百分比和百分点，耗时注明实际测量范围。缺失值保持未知，原因尚未验证时保持为解释假说。

在关键调用后显示真实输入片段、变换后的对象、中间预测或阶段指标，让读者看清处理过程。长任务的手动单元在准备、处理进度、评测与保存等关键阶段输出状态并及时刷新；进度来自实际工作量，未运行时保持待运行。能更快看清差异时用图表，少量精确数值用表格。图表直接读取本次比较数据，必要中间值帮助读者理解机制。方法名、坐标、单位和重复单位清楚；图后用一句话指出主要发现。实测、教学示意和待运行状态分别标明。

交付前由 Agent 在文档外核对当前步骤已落盘、阅读顺序和真实运行状态。管理性的源码摘要、文件完整性与历史档案检查放在执行工具或项目记录。Notebook 只呈现理解、运行与判读当前比较所需的内容。只运行已授权内容，付费、长任务和远端计算按 [Notebook 指南](mvp-notebook.md) 交付。

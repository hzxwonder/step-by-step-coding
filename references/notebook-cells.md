# 从科学问题到可交互单元

在设计、编写或修订科研 MVP 的当前教学节时使用。实验协议决定检验什么，Notebook 展示假设怎样变成方法、比较和判断。按当前问题选用以下单元角色。

| 单元角色 | 当前应有内容 | 紧接的检查 |
|---|---|---|
| 问题与判据 | 本轮子问题、竞争解释、什么观察会改变判断 | 判据在结果出现前明确 |
| 输入与条件 | 一条实际样本、数据来源、可调参数和单位 | 看见处理前后的输入与两组固定条件 |
| 关键定义 | 本轮机制、对照构造或指标的具体函数，必要时使用类 | 定义后立即用小输入调用，显示中间值 |
| 一次比较 | 使用当前定义，在可比数据和资源下运行 | 原始输出对应输入与当前实现 |
| 计算和观察 | 指标算法、分母、失败与缺失项规则，必要图表 | 小表说明数值含义与适用范围 |
| 反馈停顿 | 观察、解释、未决点与一个理解或预测问题 | 等用户回复，再修订或推进 |

一个学习步骤可由数个 Markdown 和代码单元组成。按读者需要的转折拆分，把当前定义、样例和对应输出放近。初始化与导入按功能集中，教学提问安排在可判读的观察之后。未来步骤先留研究问题，按照用户反馈增量实现。

## 研究实现与可复用依赖

新 MVP 的核心方法、比较条件与指标在当前 Notebook 直接定义。运行单元实际使用这些定义；改变本节参数或方法后，相关结果必须随实际计算更新。函数足够表达时使用函数，只有确有持续状态或对象交互才引入类。定义之后紧接具体样例，避免连续堆放尚未使用的实现。

复用成熟库、编译器、隔离、连接与通用训练基础设施。Notebook 展示调用这些能力的真实参数、输入输出契约与成本。本轮需要验证的逻辑若只存在于外部脚本，先暴露并局部验证关键定义，再进行实际比较。仅启动作业或打印历史汇总的单元用于执行准备或证据回顾，并标出其支持范围。

对于已有成熟模块，先读取实际调用链、必要输入检查和真实函数源码，在 Notebook 展示当前需要理解的片段并调用同一实现的小例子。随后只提取当前教学需要的核心逻辑。保留上游检查所保证的前提，例如输出长度、有限数与缺失结果的处理，核对提取前后行为。

研究定义维护一份来源。需要供脚本使用时，可从 Notebook 导出同版本定义并记录版本或摘要，让执行路径回到该来源。选择项目已有工具；只有确需模块导出时才评估 nbdev。Notebook 展示的定义与远端实际运行的定义须对应。

## 远程运行

内核放在具备依赖和设备的实际机器时，本格定义可直接在该环境执行。核实内核机器、当前目录、依赖和有效设备，界面网址只表明浏览器入口。可使用已授权的 SSH 隧道访问远程 Jupyter。

远程作业接口也可复用。提交前展示本轮研究定义和生效配置，返回逐项输出、执行版本与成本，再由可见指标逻辑计算结论。运行状态区分提交、完成和失败。SSH 连接与传输放在明确的适配单元，科学问题、方法与结果仍沿同一实现可追溯。

## 交付核对

- 用户能在当前节找到方法、输入、对照和指标的实际含义。
- 当前小样例调用的是展示的实现，关键改动能产生可观察的计算差异。
- 单元从干净内核按顺序运行，原始结果、配置和汇总对应同一运行。
- 当前观察明确支持、削弱或尚无法判断什么，停顿围绕现象与研究意义。

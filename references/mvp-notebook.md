# Notebook 运行与阅读交付

实验路线与单元划分见 [实验单元设计](notebook-cells.md)。路线采用后，先用 Python 标准库保存有效 `mvp.ipynb`，包含当前步骤的输入、核心定义与调用或完整手动入口，立即给出可点击文件链接。环境查找、服务启动与页面准备均在文件可阅读之后按需处理。[可运行样例](../assets/mvp.ipynb)只提供排版参考，研究内容来自当前项目。

## 运行与可读结果

首屏简述当前研究问题和 idea，二级标题对应采用步骤，三级标题区分步内小节。每步以承接前步、当前缺口和本步作用的短段开头，以当前回答和下一步证据需求收束。正文按当前实验的理解顺序组织。每轮按实验单元设计整合反馈、更新已有单元并移出重复、过时和无关内容。必要依赖／内核、运行方法、预算和停止条件在对应运行处简述一次；内部 ID、哈希、审批和管理清单留在项目记录。参数有名称与单位，核心实现、调用与解释相邻。

关系、过程或数值用图表更清楚时优先可视化，区分概念示意、教学示例与实测结果。数值图表由对应数据或运行计算，标明指标、单位与方向；图形直接标注含义，不只依赖颜色，必要图片嵌入 ipynb。关键调用后展示真实输入片段、中间对象、预测和阶段指标。长单元的代码输出阶段名、完成量／总量、已用时间与适用指标，并及时刷新。输出来自实际执行；正文保留有助理解的过程，完整日志与配置保存到已有文件。正文使用标准 Markdown，沿用已知阅读视图的核验状态。

按问题选择表达：关系与处理顺序可用示意图，类别差异可用点图／柱图，连续变化可用曲线，少量精确数值用表格。核心图或相关图组后保留 Markdown 分析，讲清关键数值的来源与对照差异、实际机制为何产生该结果，以及它对核心假说的证据作用。分析深度由问题决定，见[图后分析](notebook-cells.md#中文结果与图表)。误差条或阴影说明标准差、置信区间等实际含义及重复单位／次数，对数轴和归一化基准明确标注。符号、线型或直接文字与颜色共同标识比较对象，保持方法在各图中的名称和视觉编码一致。未取得观测时呈现方法示意或明确的待运行状态，结论与实际输出同步。

中文正文使用中文标点，代码、路径和数学语法保留原样。术语首次建立对应后统一使用，不强制中英双写。标题层级连续、段落按意思拆分；代码、表格和图中文字在用户实际窗口可读，窄窗能查看长内容，中文字体无缺字。现有样式是可调整的阅读默认，不将字号、行距、代码行数或单元数作为质量阈值。结果措辞与首读检查见[中文教学写法](notebook-cells.md#中文结果与图表)。

## 短测与手动运行

自动短测按单个代码格计时：每格预计不超过 60 秒，且运行处于已有授权内。当前采用步骤中的多个短格累计可以超过 60 秒；内核启动另设有界超时。单格超时后保存部分输出并停止后续格，不后台等待或自动重试。不得把一个长任务机械拆格来规避边界。

单格预计超过 60 秒或耗时未知时，默认写好代码供用户手动运行。已有明确的自动长任务授权直接沿用，不重复询问；单有费用或设备许可不代替执行方式授权。手动和已授权自动长任务都应显示实时阶段输出，当前步骤的交互节奏继续沿用。

| 单元标签 | 运行方式 |
|---|---|
| `quick-check` | 适合当前限时短测，显式选择必要定义与调用 |
| `manual-run` | 用户手动执行的长任务或未知耗时任务 |
| `requires-manual-run` | 依赖尚未取得的手动结果，当前不自动执行 |

标签写在单元 metadata 的 `tags` 数组。它们不阻止 Jupyter 自身执行 Run All，含手动任务时首屏与相关单元应引导用户逐步运行，并说明具体入口、预期阶段输出和结果文件。未运行单元保留空输出及真实状态。

与 Paper Factory 一起使用时，可运行 `python <paper-factory-skill>/scripts/notebook_step.py <ipynb> --cells 1,2 --timeout 60 --output <ipynb>`。`--timeout` 是每个代码格的上限。代码格从 1 编号，忽略 Markdown 格；显式指定原路径可原位保存输出，默认另存 `.checked.ipynb`。只选择本步的 `quick-check` 单元；遇到手动标签或未知耗时即停止，不推导依赖。这个入口用于离线短测，临时内核写回文件不等于已打开页面收到了实时输出。独立使用本技能时采用宿主等效限时工具；没有限时工具就保存代码供手动运行，不为安装执行环境延迟交付。

用户手动完成后，读取对应输出并核对运行身份，再完善本步结论。“继续”不代替长任务运行：缺结果时指出需运行的单元，或讨论不依赖该结果的下一步。当前代码仍在普通 Python 格定义和调用，独立导出按[实验单元设计](notebook-cells.md#定义执行与可选导出)处理。

远程硬件优先用已授权远程内核。只在用户准备运行相应单元时核实所需机器、设备和依赖。使用相对路径，在已有运行记录保留必要配置、版本与来源。历史结果标明来源，讲解变化不重跑有效实验。

## 每轮网址与内置浏览器

每轮给出文件链接及实际有效的 Notebook HTTP(S) 网址，沿用核对过的服务地址与 `/lab/tree/` 相对路径。先交付可读文件；用户明确需要浏览器或实时输出时，服务、认证和页面打开属于当前任务，继续完成并核验，不把页面长期留为后续动作。依赖或宿主能力确实不可用时，报告具体阻碍并保留文件入口，不虚构网址。

默认复用已知解释器和已核验页面。一次快速环境检查没有找到可用环境，就交付待运行代码，不遍历系统或其他项目。用户已要求页面时，在当前任务处理必要服务与登录；布局和样式仅处理影响当前阅读的内容。

准备浏览器时，核对服务根目录、目标文件及可见内容，保护未保存编辑。Codex 优先使用 `open_in_codex` 的 browser 目标和 `placement: "right"`；也可用 `cua.createBrowserTab("iab", url, {visible: true})` 打开内置浏览器。其他宿主使用其实际可用的侧边栏浏览器入口。系统 `open`、外部浏览器窗口或仅输出链接不代表已在侧边栏打开。没有侧边栏能力时直接说明。已有服务或页面变化时只检查受影响部分。普通更新复用有效会话；纯文字修改直接保存交付。摘要如实说明页面状态，未重新检查时沿用最近核验状态。

本地服务只监听回环并保留令牌认证，在实际标签内登录；聊天使用无令牌网址，凭据和 cookie 留在本机。远程地址须经授权代理或隧道可达，localhost 的指向由用户机器决定。页面可见与代码执行分别验证。

## 当前页面的实时输出

实时运行使用用户已打开 Notebook 的 Jupyter session/kernel，输出通过该页面的正常单元执行通道显示。仅在另一个临时内核运行、定时写 `.ipynb` 或在聊天里汇报，都不能当作当前页面的实时输出。核验时观察同一格在运行结束前收到新增输出；阶段完成后保存输出。长任务是否自动发起仍按单格边界和实际授权处理。

核心研究代码继续直接在普通 Python 格中定义和调用。使用成熟 SDK 时，把可读正文增量、工具开始／结束、阶段、用量与指标接到单元输出；同时保存已有原始日志。不要等待完整 agent 回复或整个训练完成才打印，避免把凭据或内部推理作为进度展示。SDK 没有增量输出时，至少显示真实阶段事件，不伪造百分比。

外部工具需要进程接口时，可在普通代码格定义下面的转发函数。它将标准输出与错误输出一起显示，同时写入项目已有日志位置。Python 子进程使用 `-u` 或等效无缓冲设置；其他程序按其流式选项调用。

```python
import subprocess
from pathlib import Path


def stream_process(command, log_path):
    with Path(log_path).open("a", encoding="utf-8") as log:
        with subprocess.Popen(command, stdout=subprocess.PIPE,
                              stderr=subprocess.STDOUT, text=True,
                              bufsize=1) as process:
            try:
                for line in process.stdout:
                    print(line, end="", flush=True)
                    log.write(line)
                    log.flush()
            except BaseException:
                process.terminate()
                try:
                    process.wait(timeout=5)
                except subprocess.TimeoutExpired:
                    process.kill()
                    process.wait()
                raise
            if process.wait() != 0:
                raise subprocess.CalledProcessError(process.returncode, command)
```

这里的转发只负责可见输出，不代替核心方法定义。进程应持续写入换行日志；SDK 的逐 token 输出改用事件回调直接打印。中断会清理本地子进程；远程任务的停止采用项目已有取消接口，不能把 SSH 连接断开当作远程任务已经停止。

任务已经在后台运行时，保留原进程和运行目录，在 Notebook 中只读跟随其已有日志或事件文件，并明确显示当前运行、阶段与累计指标。连接页面不重复发起实验。日志观察格的停止只停止观察；实验进程的状态单独显示。

# 用 Notebook 交付本轮研究问题

后续教学节只保留标题或问题，当前轮只实现当前节。干净内核验证覆盖目前已实现的单元。

从[可运行的版式样例](../assets/mvp.ipynb)借用结构，在项目中编写当前实验的 `mvp.ipynb`。样例是本地合成数据演示；项目中替换为实际问题、参数、数据、方法、对照和判断标准。Notebook 调用现有库或训练脚本时链接关键实现，能查看实际输入、命令和逐项输出。保持底层逻辑单一，便于将稳定部分用于正式实验。

1. **首屏说明怎么看。** 短标题、一个问题、数据范围、依赖与内核、从头运行方法、成本和停止条件，指明要核对哪个输出。已有准备好的输入时，首个本地探测优先约 5 秒；记录准备、冷启动与实际运行。样本过小会丢失现象时选最短的有效比较，并说明原因。
2. **一节一问。** 编号的小标题下先用一句话写目的和应看什么，再给可运行代码。首段集中放可调参数和单位；显示一条样本，再运行同条件比较。核心操作与计算保持可见。专有名词先用实例解释，机制、边界和误解放在按需阅读段落。
3. **输出保留判断需要的内容。** 表格有指标名、单位与方向，图形有直接标注且不只用颜色区分。只展示代表行或一个必要图；长日志、原始结果和配置保存在可复查的文件。使用标准 Markdown 标题、短段、引用和留白，让 GitHub、JupyterLab 和静态 HTML 都可读。
4. **交付前从干净内核运行全部单元。** 使用相对路径，记录内核、数据来源、实际配置、随机设置和耗时；结果来自当前运行。默认 Run All 仅执行已授权且可重复的低成本操作。付费、远程训练或长任务显式选择后才启动，默认可检查已有结果；保留未运行状态和原因，不将其记为实测。提供实际复现入口和已运行版本。
5. **最后写下证据边界。** 观察、解释（实测／文献／推测／待测）、下一步及理由、证据链接。与上一轮比较时写清改动，尤其是数据、监督和评测条件。只有用户要求写论文时才同步草稿。

使用原生 Markdown 一级标题、引言和单行阅读路线。首屏写明要改的参数和要观察的结果。用随运行重新计算的内嵌 PNG 展示适合图示的比较，配上单位、数值和文字结论。用干净内核验证图片和正文都存入 ipynb。网页预览样式仅影响导出视图。

在 Paseo 可为项目登记仅监听本机回环的 JupyterLab workspace service，以项目为根，保留 Jupyter 登录令牌，在浏览器打开 /lab/tree/ 加实际 Notebook 路径。静态 HTML 用于阅读。远程计算通过明确选择的单元调用已授权 SSH 主机，默认 Run All 读取已有证据；新结果使用独立路径，展示机器、设备和实测耗时，费用和资源边界沿用用户授权。

## 每轮交付网址并打开浏览器

首次生成 Notebook、更新当前教学节以及交付或等待用户反馈时，在聊天中给出同一份 Notebook 的可点击 HTTP(S) 网址。用当前服务实际地址和 Notebook 相对路径组成 JupyterLab 的 /lab/tree/ 入口，正确编码空格与中文路径。沿用会话记录中的有效地址，服务重启或地址变化时重新核对。给出当前文件链接，便于下载源码。

先发现并复用项目已运行的 Jupyter 服务或 Paseo workspace service。核对服务根目录覆盖目标文件、文件实际存在，以及入口可达。需要登录时注明登录方式，使用服务终端提供的令牌，聊天网址保留无令牌地址。将完整终端启动输出、cookie 或服务凭据留在本机。远程服务使用宿主代理或已授权 SSH 隧道形成用户可访问的地址；用户浏览器所处机器决定 localhost 指向哪里。

宿主支持内置浏览器时，主动打开或复用 Notebook 标签页，并检查目标页面是否加载。Codex 可通过实际可用的 open_in_codex 浏览器面板或侧边栏浏览器工具打开；Paseo 使用当前 workspace 的服务预览或侧栏浏览器；其他宿主先发现可用能力。已有标签优先复用，保留用户未保存的编辑。浏览器调用失败或停在登录页时，报告实际状态并保留可点击网址，继续当前教学反馈。

服务未就绪时先完成已授权的本地启动准备。缺少依赖、端口、转发或权限时，说明具体阻碍和最短下一步，将可核对的预期地址标成待启动。打开页面成功与执行代码分别验证，交付时写清已经做到哪一步。

每轮简短附上以「打开当前实验」为文字的 Notebook 网址链接，再用一行报告「浏览器已打开」「等待登录」或「需手动打开」等实际状态。

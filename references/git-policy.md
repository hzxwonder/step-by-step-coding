# 本地保存与可选远程推送

默认只保留本地。未要求远程备份时，Agent 可直接记录 `configure-git --mode off`，无需为本地实施追加保存方式提问。此默认值不代表用户授权 commit 或 push。

## 启用远程推送

用户明确要求推送时，只补齐缺少的信息。一次只问一个关键缺口，已有信息直接沿用。

1. 明确目标平台、已授权仓库和 remote。已有 `origin` 不能代替用户授权。
2. 明确功能分支，以及是否每个验收版本都提交推送。主分支、改写历史、创建远程仓库或修改可见性需专门授权。
3. 检查现有分支、用户改动和本机认证。不要索取密码、token 或私钥。

同一句用户指令明确提供全部信息时，可以一次记录。无需按平台、仓库和分支逐轮重复确认。

## 验收后提交推送

确认当前版本有真实验证与验收原话。讲解文档供按需阅读，不要求用户先完成代码学习。

检查 `git status`、diff 和未跟踪文件，按精确路径暂存。不要使用 `git add .` 或混入无关修改。密钥、私有数据、个人原话和本地状态默认不提交。真实日志、prompt 与配置快照也须检查是否包含敏感内容。

审查暂存区后创建新提交，推送到已确认 remote 和分支。记录返回码、提交 SHA 和目标。修改已推送版本时增加新提交，不改写已有历史。

失败时保留本地工作并报告具体错误，不擅自 force push、换 remote、merge 或 rebase。当前步结算成功后，仅在下一步也有明确授权时继续。

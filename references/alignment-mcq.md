# 记录约定并处理待定项

此文件供 Agent 维护内部记录。用户只需用日常语言表达期望，不需要回答字母或操作状态脚本。

## 默认直接记录约定

`preacceptance.md` 记录关键行为与真实证据，不是知识考试或必答问卷。每项从 Q1 连续编号，数量按实际需要。详细标准引用步骤计划，不抄成多份。

```markdown
### Q1 缺失金额的处理
- **当前约定**：金额缺失时保留为空，并提示检查原记录。
- **证据**：步骤计划的金额规则，以及本次实际 prompt、日志和结果中的对应记录。
- **分歧处理**：规则变化影响 prompt、金额解析与相关 case，需要重验。
```

已有明确要求或委托且实测一致时，引用原话直接登记：

```text
answer-precheck --id Q1 --user-answer '<真实原话>' --summary '<原话适用范围与核对结论>' --evidence '<实际证据>'
```

命令由 Agent 执行。语义判断由 Agent 负责，脚本只检查记录和状态。没有反对、“我懂了”或含混回答不能当作同意。不要为完成内部登记重新询问已经明确的决定。

## 需要选择时才使用选项

有真实取舍时，先说明现状、推荐及原因，一次只问一个决定。用户可以直接描述期望。示例：

> 再次运行时，旧结果可以被替换，也可以保留为另一份文件。
> 我建议保留旧结果，方便比较。
>
> **你希望保留旧结果吗？**

内部可以沿用以下选项格式。它与直接约定不能混写在同一条目中。

```markdown
### Q1 重跑后的保存方式
- A. 保留每次运行的结果。
- B. 只保留最新结果。
- D. 其他想法或需要讨论。
- **当前约定选项**：A
- **证据**：计划中的保存规则，以及本次重跑结果。
- **分歧处理**：调整保存规则并重跑相关 case。
```

这类条目使用 `answer-precheck --choice ...`。仅映射用户明确表达的意思，保留真实原话。未提供的选项不能使用。

## 分歧与修订

- **仍有疑问**：直接约定可使用 `--needs-discussion`，选择项可使用 D。先解释差别，不记录为已对齐。
- **明确保留当前行为**：用 `resume-precheck --user-quote ...` 记录本次原话。
- **需要修改行为**：按相应授权修订，并用 `revise --affected Qn` 标记受影响项。验证后更新证据，未变化的确认保留。
- **只整理内部条目**：使用 `reset-precheck` 重新锁定。引用已有的对应要求或澄清原话，不为整理记录另问一次许可。涉及新行为时仍须先取得确认。
- **只补充讲解**：直接更新 `explain.md`，不重跑已完成验证，也不撤销确认。讲解暴露实质错误时转入修订。

`start-precheck` 锁定约定、计划、验证与获批文件。关键 prompt、配置或运行证据若会影响判断，应列入当前步文件范围。此后改变这些内容，需要重新核对证据，不能沿用旧运行结论。

## 记录验收

必要约定有真实确认与证据后，用户明确接受当前结果即可验收。若同一句话明确覆盖整份结果与各项约定，可分别登记到对应条目和 `accept`，无需分轮提问。

只接受一条细节不能扩大为整步验收。接受当前步也不自动授权下一步。用户同时明确表示接受当前步并开始下一步时，按顺序登记两个决定。
